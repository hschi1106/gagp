# Final Scale Experiment (2026-11-03)

This directory holds the protocol, harness, configuration and compact results
of the final GAGP experiment. The analysis and its interpretation are in the
[final report](../../docs/reports/gagp-final-report.zh-TW.md); the numbers are
in [`results/results.md`](results/results.md).

## Question

With 1024 training cases and population sizes 1024, 4096 and 16384, on the 30
program-synthesis tasks of the ASGP paper:

1. **Speed.** How much faster is a complete GAGP search on the GPU than the
   same search on GAGP's own CPU reference engine, and than the original ASGP
   solver on one thread (ASGP-1T)? How does the speedup change with the
   population size?
2. **Exactness.** Do the GPU engine and the CPU reference engine publish the
   same search?
3. **Evolutionary ability.** Do GAGP champions solve the held-out test cases
   as often as ASGP-1T champions, at each population size? What does a larger
   GAGP population buy within (or below) ASGP-1T's time at P1024?

## Arms

All arms start from the same frozen inputs: per task and seed, one
ASGP-initialized population of 16384 programs (smaller populations are its
prefixes) and the same 1024 training cases.

| Arm | Mode | Runs |
| --- | --- | --- |
| `gagp` | `search_gpu_overlap`: GPU reproduction + GPU evaluation, final search profile [`gagp_final_asgp.json`](../../configs/search/gagp_final_asgp.json) (synchronous steady state, batch = P), G64 | 30 tasks x 3 P x 5 seeds |
| `asgp` | `search_asgp_1t`: original ASGP solver, one thread, generational, G64 | 30 tasks x 3 P x 5 seeds, as far as the time budget allowed |
| `cpuref` | `search_phase_cpu`: GAGP CPU reference engine, same configuration, G64 | 30 tasks, P1024, seed 1 |
| `gagp_clean` | The `gagp` runs repeated with the committed engine (commit `0178362`, engine-profile defaults; no engine switch, no diagnostics or trace). Every run must reproduce its `gagp` run exactly; its times are the headline speed numbers | 30 tasks x 3 P x 5 seeds |
| `gagp_gen` | `search_gpu_overlap` with the generational schedule ([`phase_asgp_site7.json`](../../configs/search/phase_asgp_site7.json), otherwise identical), G64; schedule ablation added once the GPU queue had finished early | 30 tasks x 3 P x 5 seeds |
| `gagp_g8`, `cpuref_g8` | GPU and CPU reference engines with the same profile at G8 ([config](config/gagp_final_asgp_g8.json)) | 30 tasks, P4096 and P16384, seed 1 |

The CPU reference at full length (G64) for P4096/P16384 would take days; the
G8 runs measure the same engines on the same populations for the first 8
generations, and the G8 GPU history is checked to be a prefix of the G64 run.

Common search parameters are aligned with ASGP (tournament 2, crossover 0.7,
mutation 0.3, one phase per operator, depth 7, elitism or best-member
protection 1, ASGP fitness metric with case-error cap 1000, fuel 2,000,000).
GAGP's schedule (steady state, B = P) is a declared difference; the `gagp_gen`
arm measures it against GAGP's generational schedule at every population
size.

## Data

- Cases come from ASGP's task generator (`bench dataset`, data seed 20261103).
  Training cases are the first 1024 rows of the generated training pool,
  duplicates kept. The test split is up to 1000 unique inputs from the
  generated test pool that do not occur in the training split.
- Five tasks have finite input domains (fibonacci, tribonacci, even_squares,
  sum_of_squares, fibonacci_array). There, 20% of all unique inputs (in a
  fixed hash order) are reserved for test and removed from training, so their
  test splits have 6 to 34 cases. Sizes are in
  [`results/split_meta.json`](results/split_meta.json).
- Population seeds 1 to 5 (`GAGP_FREEZE_POPULATION_SEED`), run seeds equal to
  the population seed. Task grammars: the 2048-node task grammars generated by
  `tools/gagp_tools/experiments/fixed_asgp/grammar.py`
  ([`config/grammars/`](config/grammars/)).

## Measurement

- Search time is `evolve_wall_ms` (initial evaluation through final
  population; no input loading or translation). No run was profiled.
- The `gagp`, `gagp_gen` and `cpuref` arms ran the binary of commit `51aa1dc` with the
  formal settings, which also enable `GAGP_GPU_DIAGNOSTICS` and `GAGP_SEARCH_TRACE`
  (extra counters and per-generation output, 1.4% slower in geometric mean). `gagp_clean`
  reruns the same searches with the committed engine and no diagnostics; the seed-1
  `gagp_clean` cells were run a second time to measure timing repeatability
  (`results/repeat.json`).
- Host: Intel Core i9-10900K (10 cores / 20 threads), one RTX 3090, CUDA 12.6
  ([`results/environment.json`](results/environment.json)). All arms preload
  jemalloc and use `GAGP_HOST_THREADS=1`.
- GAGP GPU runs execute one at a time under the GPU lock, pinned to one core.
  ASGP-1T and CPU reference runs execute on 8 single-thread workers pinned to
  8 other cores. Input preparation, builds and judging use the remaining core.
  Because ASGP-1T ran 8-wide, a subset was rerun alone to measure the
  contention factor (`results/isolation.json`, reported with the speedups).
- Quality: every run exports its final champion; `bench quality-source`
  re-scores it on the CPU on the test split and on the training split. A run
  "solves" a task when its champion is exact on every test case. Paired
  comparisons use exact McNemar tests and a 95% bootstrap interval that
  resamples tasks (10000 draws).
- Exactness: for `cpuref` vs `gagp` (and the G8 pair), the champion export
  must be byte-identical and the per-generation history identical apart from
  timing fields.

## Time budget and order

The experiment had a 24-hour budget starting 2026-11-03 01:54. The CPU queue
ran ASGP-1T seed 1 (all P, longest first), then the CPU reference runs, then
ASGP-1T seeds 2 to 5 at P1024, then at P4096, then P16384 seed by seed; a job
started only if its estimated duration fitted before 21:54. (The queue was
restarted once at 07:01 to apply this order to seeds 2 to 5; one in-flight
ASGP-1T run was restarted from scratch.) The GPU queue ran seed by seed, then
the `gagp_gen` arm, the `gagp_clean` arm and the timing repeat. Cells that did not run are
listed as missing in the results; no cell was dropped after it ran.

## Reproduce

```bash
# build gagp_fixed_asgp_bench (see docs/guides/fixed-asgp-benchmark.md), then
export GAGP_FINAL_SCALE_DIR=$PWD/logs/final-scale-20261103   # data directory
export GAGP_FINAL_SCALE_BIN=$PWD/cpp/build/release/gagp_fixed_asgp_bench
# set config/settings.json LD_PRELOAD to a local libjemalloc.so.2 (or remove it)
python3 benchmarks/final-scale-20261103/tools/prep.py all 1,2,3,4,5 4
python3 benchmarks/final-scale-20261103/tools/run.py gpu 1,2,3,4,5
python3 benchmarks/final-scale-20261103/tools/run.py cpu 1,2,3,4,5 8 DEADLINE_EPOCH
python3 benchmarks/final-scale-20261103/tools/run.py gpugen 1,2,3,4,5     # gagp_gen arm
python3 benchmarks/final-scale-20261103/tools/run.py gpuclean 1,2,3,4,5   # gagp_clean arm
python3 benchmarks/final-scale-20261103/tools/judge.py 2
python3 benchmarks/final-scale-20261103/tools/analyze.py OUTDIR
python3 benchmarks/final-scale-20261103/tools/charts.py OUTDIR/results.json OUTDIR
```

The recorded runs used the binary built from commit `51aa1dc`, with the exact
engine settings passed explicitly ([`config/settings.json`](config/settings.json));
with the engine profile of later commits the same values are the defaults.
Raw outputs (populations, logs, exports, histories; about 15 GB of inputs)
stay in the data directory.

## Files

| Path | Content |
| --- | --- |
| `tools/common.py` | Tasks, populations, seeds, paths, run environment |
| `tools/prep.py` | Case pools, train/test split, frozen and translated populations |
| `tools/run.py` | GPU and CPU job queues, resumable records |
| `tools/judge.py` | Champion re-scoring on test and train |
| `tools/analyze.py` | Speed, exactness and quality statistics |
| `tools/isolation.py` | Reruns a subset of CPU jobs alone to measure the 8-worker contention factor |
| `tools/verify_clean.py` | Reruns the seed-1 P1024 cells with the committed binary (GPU or CPU reference) and compares them with the recorded runs |
| `tools/repeat_clean.py` | Second committed-engine run of the seed-1 cells (timing repeatability) |
| `tools/charts.py` | Report figures from `results/results.json` |
| `tools/ctest_key.sh` | The native tests run before the experiment |
| `tools/quality_data.py` | Input identity helper (vendored) |
| `config/` | Engine settings, G8 configuration, task grammars, ASGP time estimates used for ordering |
| `results/` | Run records, judge summary, split sizes, environment, analysis tables |
