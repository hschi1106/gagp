# GAGP 全30題額外加速與品質驗證

P＝每代個體數；G＝演化代數；C＝評分案例數。基準是上一個最快GAGP，候選是本輪凍結版本；加速比＝基準搜尋秒數÷候選搜尋秒數，大於1才是變快。

搜尋秒數與倍率均為合格格子的幾何平均。搜尋wall time涵蓋演化呼叫內的初始化／匯入驗證、GPU評分與繁殖、最終評分與族群還原；呼叫前的JSON解碼、grammar／AST準備，以及呼叫後的CPU16核對與匯出另計程序成本。缺失、失敗與核對未完成的格保留；不完整範圍的平均不代表全題達標。新程序重複倍率範圍是描述性變動，並非跨題泛化信賴區間。

目前全題計時觀測為1.477×，未達2×。若固定本輪基準與工作量，候選版搜尋時間的幾何平均仍需再降低26.1%才達標。這是距離目標的算術換算，不是新優化已能取得的收益；完整核對不足時仍只能列計時觀測。

部分格的額外原生核對未齊，不能把上表已核對子集的平均當作全題平均。另列尚未套用額外原生核對篩選的實際計時觀測：P=1024：1.217×（量測與配對檢查30/30格）；P=16384：1.793×（量測與配對檢查30/30格）；兩種P合併：1.477×（量測與配對檢查60/60格）。這些數字不替代已核對結果或達標判定；未完成／失敗仍保留。

## 本輪採用的機制

| 機制 | 工作方式 |
|---|---|
| 相同案例合併 | 有效輸入及答案完全相同時只執行一次，按重複次數累計分數與wrong。 |
| 輸入形狀結果重用 | 僅限已證明不讀取串列元素、回傳純量的程式；形狀及有效純量參數相同才重用結果。 |
| 未改變子代沿用分數 | 基因型及資料版本完全一致時，沿用前一代已完成的GPU分數。 |
| 跨父代查找已完成分數 | GPU先以hash找候選，再完整比較基因型；碰撞或查找失敗就正常評分。 |
| 相鄰不可變串列共用儲存 | 兩段資料在同一儲存區相鄰時，以區間表示串接結果，省去再次複製。實際寫入位置與配置額度分開記錄；長度、邏輯配置、容量上限及溢位重跑規則保留原值。僅限已通過驗證的私有連續整數串列。 |
| 單菁英線性選取 | 用O(P)選出唯一菁英，保留原fitness及index的排序規則。 |
| 評分／繁殖共用儲存區 | 順序重用16GiB空間；另列64KiB對齊成本，減少兩階段同時保留的配置。 |
| 繁殖核心block | 1 threads；每個子代的RNG與運算不變。 |

這些機制共同構成上表的候選；整體倍率不能解讀成各機制的個別收益。完整族群／逐代冠軍與原生CPU核對用來檢查執行是否改變；獨立seeds另檢查演化品質。

完整族群核對有1組因程序中斷而無法判定，保留為interrupted，未重跑。其他尚未開始的核對使用原binary、輸入與設定接續；所有已完成搜尋均未重跑。中斷核對的子程序耗時只有最後觀測下限，實際成本與已執行個體數未知；不能列為核對通過。詳見interrupted_native_audits.json與原始native-resume1/2紀錄；第一次恢復腳本在啟動任何核對前因PID狀態別名錯誤退出，第二次只修正狀態複製，保留第一次失敗。

備援0在資料生成與樣本執行前，因啟動記錄的文字不符檢查而停止。原始紀錄保留；備援1修正記錄標記，版本、輸入、截止時間、資源與P/G/R/種子逐項一致，沒有重抽或替換任何樣本。核對證明見empty_startup_recovery.json。
