# 大 population GPU 加速結果

**全部正式搜尋與核對完成。P=1,024／16,384，G=8，每個體 1,024 案例；30 題、3 方法、同 seed0 的 2 次冷程序量測，共 360 筆。**

程序原始成功 360/360；獨立工作量／來源核對成功 360/360；完整合格速度格 60/60；final 與逐代 champion CPU 判題 360/360。

先看這張表的 ASGP／優化 GPU：10× 表示完成這批固定代數工作所需的搜尋時間約為 ASGP 的十分之一。原 GPU／優化 GPU 則回答這條 tuple 執行路徑本身帶來多少收益；小於 1× 的負收益保留。跨題平均只使用合格題，分母始終明列；失敗與缺失均保留在逐 run CSV。

P 是每代個體數，G 是演化代數。ASGP 初代從同一凍結來源族群依序取前 P 個體；GPU 使用對應的 prepared 初代，原 GPU 與優化 GPU 共用同一檔案。seed0 指演化亂數；兩次冷程序量測沿用相同初代與案例，不重新抽個體，也不把失敗個體換掉。因此兩次只用來看計時波動，不能當成兩個獨立的品質 seeds；固定輸入也不代表 ASGP／GAGP 後續算子分布相同。

## CPU 核對與額外成本

正式成功搜尋累計 6.083 小時；搜尋計時之外的原始 fitness／wrong CPU 核對 4.222 小時。所有正式程序 wall 累計 10.658 小時（含額外核對／匯出／失敗嘗試）；final＋逐代冠軍 CPU 判題程序另 0.107 小時。這些累加成本不能全部套用搜尋加速比；也不等於整個24小時窗口，還有開發、hash、診斷與報告時間。

原始 native CPU fitness 核對 1,046,400 次個體觀測、wrong 核對 1,046,400 次；fitness 差異 0、wrong 差異 0。這些次數包含兩GPU／不同population／重複工作，並非互不重複的新程式。程序失敗或核對無效的資料不當作已驗證觀測。

搜尋計時內的 GPU 方法 CPU training guard：0 次個體、0.000 秒，fitness 修正 0 次、wrong 修正 0 次。這個正式 execution-only arm 關閉 training guard，核對其設定、總量及各代紀錄皆為0；搜尋後的離線 CPU 核對另列，不注入、改分或重新挑冠軍。

第一個 repetition 的兩個 GPU 方法都核對全部最終個體，並比較完整最終 AST；第二次核對前 16 個體及 final descriptors／每代 champion AST、fitness。這不證明所有世代的全族群一致或任意輸入的語意等價。GPU 使用評分及繁殖，無 CPU 繁殖替代；完整性判定另核對 unscored=0、各代案例量及實際 reproduction profile。

## 本輪做了哪些優化

正式優化組採用 tuple execution-only 路徑，保留 512 評分分組，沒有調換算子或增加 CPU training guard。這條既有路徑在本輪被擴展到 P16384 的容量／全族群核對及全30題同輪控制；不把它描述為本輪新發明。

本輪實作並測試 compact-root 小陣列 VM 原型；20 組完整程式／分數配對通過，但平均只快約 0.9%，未達事先訂定的 3% 門檻，已封存並移除。較小分組整體較慢；1024 分組平均約快 6.4%，卻有一組完整程式不同，亦淘汰。保留所有失敗／負結果，沒有放寬門檻或重挑正式資料。

固定父代診斷：30 題的程序狀態 {"ok": 30}；明列 phase-root 替換狀態 {"ok": 296, "mapping_unavailable": 40}。只覆蓋前8個未改父代／4組配對的 phase root；不涵蓋內部位置、mutation generator 或隨機取樣分布。五個動態規劃題的無法映射紀錄保留，不能據此認定與既知四題 HeadIndex site-count 差異原因相同。

全部 ASGP 分母來自本輪新測速。正式前按固定時間規則選 G8／2次，預估完整程序及全族群 CPU 核對 14.513 小時、另留 4 小時；歷史數據只用於這個預算，未混入正式倍率。
