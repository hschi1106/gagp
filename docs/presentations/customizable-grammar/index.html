Can we discover “double the number”?

Suppose we want a program that takes a whole number and returns twice that number. We will use this small problem throughout the report.

InputWanted output
24
510
−3−6

We could write n + n ourselves. Here, we want GAGP to discover a program from examples. Our job is to choose the building blocks it may use and the rules for putting them together.

This report starts with that concrete task, then introduces more powerful building blocks and explains what changes when programs run on a GPU.

Remember: You do not need to know compiler terminology. Read the examples first; each technical term is explained when it becomes useful.

Start with three building blocks

n          Read the input number.
0          Use the fixed number zero.
add(A, B)  Add the results of two smaller expressions.

If n = 5:
  n             gives 5
  add(n, n)     gives 10
  add(n, 0)     gives 5

An expression is a piece of a program that produces a value. The letters A and B above are places where other expressions can go.

GAGP already knows how to execute addition. We are deciding whether addition is available to this search, and what may be placed inside it.

Remember: Writing a custom grammar usually means combining existing operations. A new operation that GAGP does not understand requires changes to the native implementation.

GAGP / 01 / Start with one problem

One rule describes many programs

E → n
  | 0
  | add(E, E)

Read this as:
“To build an E, choose the input, zero, or an addition of two Es.”

The arrow means “may be built as.” The vertical bar means “or.” E is just the name of a reusable rule. The formal name for a rule like this is a nonterminal.

The third choice uses E again. This allows larger expressions to be built from smaller ones. Each choice is called an alternative or production.

There must be a way to stop expanding. Here, choosing n or 0 ends that branch. A rule containing only add(E,E) would never finish.

Remember: A grammar is a set of construction rules, not one finished program.

This branching picture is called a syntax tree, or AST. The root operation reads the results of its children. For input 5, both children produce 5 and the addition produces 10.

Another round of choices might build add(n,0). A deeper one might build add(add(n,n),0). They all follow the same rule, although they do not all solve the task.

Remember: The grammar permits many possible trees. The search must find useful ones among them.

Legal does not mean correct

CandidateOutput for n = 2Output for n = 5Solves these examples?
000No
n25No
add(n, 0)25No

Every row is allowed by our grammar. Only the last row gives the wanted answers here. GAGP runs candidates against the cases and assigns a score called fitness.

Better-scoring candidates influence which parents are selected. New candidates may combine compatible pieces from parents (crossover) or change a piece (mutation). The resulting programs must still satisfy the grammar.

Passing examples is evidence, not a general proof. Include negative numbers, zero and other meaningful cases instead of checking just one input.

Remember: Grammar checks legality. Fitness checks how well a legal program solves your examples.

GAGP / 02 / Choose the language

A smaller language can be easier to search

Allowed rulesWhat changes?
E → n | 0No candidate can double every input: addition is missing.
E → n | 0 | add(E,E)The answer n + n is available.
Also allow multiplication, lists and textThere are more possible constructions to explore; the extra choices may not help this task.

A useful grammar includes the operations needed for a solution without adding unrelated choices. Too narrow, and the answer cannot be expressed. Too broad, and the search has more irrelevant candidates to consider.

You can change the language without rebuilding GAGP: add an existing operator, remove a choice, change allowed constants, or prescribe a larger structure.

Remember: Before tuning the search, ask: “Can my rules actually express the answer I want?”

GAGP / 02 / Choose the language

Some tasks need several steps

Conceptual program:
  total = 0
  repeat for i = 0, 1, 2:
    total = total + i
  return total

The returned answer is 3.

A statement performs a step in a program. GAGP supports assigning variables, choosing between blocks with an if-statement, repeating a block with ForRange, and returning an answer.

A mutable local variable such as total holds a value that later statements can update. Its type stays fixed. It must be initialized before it is read.

ForRange evaluates its non-negative integer bound once. It is a specific supported loop form; GAGP does not provide while, break, continue, arbitrary user functions, file access or network access.

Remember: You can build multi-step programs, but only from the control structures GAGP provides. The example above explains behavior; it is not JSON authoring syntax.

GAGP / 02 / Choose the language

To process a list, carry a running answer

Suppose the task changes: instead of doubling a number, we want to add every element in a list. A traversal can visit the elements one at a time while carrying a running answer.

StepCurrent elementRunning answer
Before the first element—0, the starting value
Visit element 120 + 2 = 2
Visit element 252 + 5 = 7
Visit element 387 + 8 = 15

GAGP calls this Traverse. You supply the sequence, a starting answer, and a step expression. The step can read the current element, its index, and the current running answer, called the accumulator.

Those names exist only inside the step. That area of visibility is their scope. The names are immutable within one step; the step’s result becomes the accumulator for the next step.

Remember: An empty list returns the starting answer. Related forms support reverse order or a selected interval. LetRegion is another scoped form: calculate one value, name it, then use it inside a body.

A domain is simply an allowed set of values. It can list specific constants, specify a numeric range, or describe a sequence’s length and elements.

Weights are preferences, not quotas. Addition cannot be selected when there is too little room for its children. Program-size limits include the generated program structure, not just the expression drawn on page 5.

Remember: Size limits and execution limits answer different questions: “How large may the program be?” and “How much work may it do?”

GAGP / 03 / Write your own rules

Fix the shape; search only the missing piece

Sometimes you know the overall formula already. For example, you want “take some expression and add it to itself.” You only want to search for that expression.

Fixed shape:       add(H, H)
Allowed fillings:  H = n   or   H = 0   or   H = add(n,1)

Examples:
  add(n, n)
  add(0, 0)
  add(add(n,1), add(n,1))

A template is a fixed shape with named openings called holes. Each hole declares the type of result it expects and the names it may use.

Here, both H occurrences mean the same logical hole. They receive the same chosen expression and change together during variation. They still become two physical copies in the program, so both copies count toward its size.

Remember: Templates let you use knowledge about the solution’s structure while leaving selected decisions to evolution.

Reuse a larger recipe from a package

For a task that divides a list into smaller problems, you can reuse a package instead of rebuilding the whole recursive structure.

Fixed recipeSplit the problem and solve the smaller parts.
Open decisionsChoose the source, small-case answer, split and combination.
Your custom grammarFill each opening with rules suited to the task.
The combine opening receives two child answers:
  left : Int       right : Int

Your rule may choose:
  add(left, right)     Combine by addition.
  max(left, right)     Keep the larger answer.

A package is a reusable grammar file. Import it using a relative path, then provide rules for its template holes. The combine rule can use left and right because the hole declares those names in its scope.

Remember: Importing a package reuses data and structure. It does not add arbitrary executable code. Use extend to append choices to an imported rule, or replace to replace a resource completely.

GAGP / 03 / Write your own rules

Recursion must show how it gets smaller

Recursion solves a problem by asking for answers to smaller problems. Without a clear stopping rule, it may keep asking forever.

A useful split:
  [2, 5, 8, 1]
     → [2, 5] and [8, 1]
     → smaller subproblems until the base case applies

A bad request:
  solve the same whole problem again, with no progress

GAGP uses a BoundedRegion: a declared plan for state, smaller requests, stopping conditions and how to combine child answers. For sequence problems it checks proper subwindows. For coordinate problems it checks that requests decrease a declared ordering.

Memoization means saving a subproblem’s answer for reuse. A frame is a record of an unfinished recursive call. Both need explicit capacity limits; arbitrary recursion is not available.

Remember: A valid recursive shape needs a progress argument as well as storage limits. Nested BoundedRegion calls inside its phase bodies are forbidden.

GAGP / 04 / Understand GPU limits

The GPU runs programs prepared by the CPU

CPU: prepareTurn each candidate tree into executable instructions.
CPU: uploadSend instructions, inputs and supporting data to the GPU.
GPU: evaluateRun candidates on the test cases and produce fitness results.

The instruction format is called bytecode. A small execution engine reads those instructions on the GPU. GAGP does not turn an arbitrary JSON operation into a new CUDA function.

The GPU evaluates many cases in parallel, but each case still needs its own temporary values, local variables and any recursive bookkeeping. These per-case resources are bounded.

GPU evaluation and GPU reproduction are separate choices. You can evaluate on the GPU while creating the next generation on the CPU.

Remember: A legal grammar still has to produce programs that fit the GPU execution profile.

GAGP / 04 / Understand GPU limits

Each case has limited working space

Think of one case as a calculation with a small workbench. Uploaded inputs are available, but temporary calculations and newly built results need working space too.

Working spaceWhat it holdsCurrent GPU limit
Operand stackTemporary values waiting for the next operation.64 values
Local slotsInputs, named variables and compiler-created helper variables.64 per code object
Region framesUnfinished recursive work.128 declared per region
Memo cellsSaved subproblem results.128 declared per region

A short source expression can introduce helper variables when compiled. Conversely, AST depth is not the same quantity as operand-stack depth. You must check the compiled program rather than compare those numbers directly.

Region declarations above the GPU limits are rejected before upload. During execution, exhausting the declared frame or memo capacity yields Timeout.

Remember: These are limits of the current GAGP GPU implementation. Increasing the grammar’s tree-size limit does not increase them.

GAGP / 04 / Understand GPU limits

A short program can build a large result

Start with text s of length 100.

concat(s, s)                         length 200
concat(concat(s, s), concat(s, s))    length 400
Double again                        length 800

The program is compact, but its intermediate and final text can grow quickly. The actual characters or list elements are called the value’s payload.

Exact output construction uses bounded per-thread scratch: currently 32 payload entries, 512 string bytes and 128 list Values. Those capacities are shared working space, not universal maximum input lengths. Several smaller intermediate results can also consume it.

When exact contents cannot be materialized, some operations use a fallback: a deterministic internal substitute. A list may retain its type, hash and length without retaining all expanded elements. Other operations can fail when exact contents are missing.

Remember: A substitute that is repeatable is not necessarily a complete answer. If the next step needs to inspect an element, a hash and length are insufficient. More fuel does not create more payload space.

Four different limits need four different fixes

What went wrong?Why?What to inspect
A candidate cannot be generated.The chosen structure cannot fit the grammar’s construction budget.Rules, terminating choices, maximum nodes and depth.
A case runs out of fuel.It performs more charged work than allowed.Input size, loops, recursive work and the fuel setting.
A region does not fit the GPU profile.Declared frame or memo limits exceed device support.The bounded plan and whether this workload fits the GPU backend.

Fuel is a work allowance, not elapsed milliseconds. It is charged by executed instructions or defined execution events. A larger input may need more fuel even when the program tree stays identical.

Some restrictions apply to both backends: exact types, the fixed operation catalog, no arbitrary I/O, and restricted recursive forms. Others, such as these device storage capacities, belong to the current GPU profile.

Remember: First identify which limit was reached. Increasing an unrelated limit will not solve the problem.

GAGP / 05 / Try it yourself

Design a grammar in seven concrete steps

  1. Write example answers. For doubling: 2 → 4, 5 → 10, −3 → −6.
  2. Choose the data types. One Int input and one Int result.
  3. List useful building blocks. Start with n, 0 and addition.
  4. Write rules that can finish. E may become a leaf or an addition of two smaller Es.
  5. Set separate budgets. Allow a small program and enough execution work for the cases.
  6. Generate and inspect programs. Confirm that useful answers are expressible and generated candidates match your intent.
  7. Check the intended backend. Test normal and boundary inputs; inspect errors and exact sequence behavior before scaling up.

You can now read “typed grammar with scoped template holes” as “rules for compatible pieces, with named openings that can only use specified values.” The terminology describes the construction rules you have already seen.

Remember: Start with a language you can explain using a few example programs. Expand it when the task requires more expressive power, and check its resource needs as you do.
