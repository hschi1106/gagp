# PSB Workflow

This guide covers PSB dataset preparation and release-2 regression runs.
Runtime, grammar, and fitness semantics remain owned by `spec/`.

## Dataset preparation

Fetch upstream rows into a local mirror:

```bash
python3 tools/fetch_psb_datasets.py --suite psb1 --out-dir data/psb1_datasets
```

Convert a problem to `fitness-cases`:

```bash
python3 tools/convert_psb_to_fitness_cases.py \
  --input data/psb1_datasets/count-odds.jsonl \
  --out data/fixtures/psb1-current/count-odds.train.json
```

For maintained batches, use `materialize_psb_fixtures.py` with the checked
schema overrides under `configs/psb_schemas/`. Keep downloaded datasets and
generated fixture trees out of committed benchmark evidence unless their
owning policy explicitly includes them.

Inspect each inferred schema. Empty lists do not establish an element type;
ambiguous inputs require an explicit schema override. Fixtures retain exact
`IntList`, `FloatList`, and `StringList` tags.

## Choose a compiled definition

Every release-2 run requires `--grammar-definition`. Use one checked
`grammar-definition-v2` whose exact input and return schema matches the
problem. Filenames do not enable constructs. The resolved definition hash,
cases hash, execution limits, and seed belong in the run record.

If a study begins with a release-1 `grammar-config`, convert it offline for
each exact schema and archive the migration report. Do not pass it to the
production runner.

## Regression sweep

```bash
python3 tools/run_psb_regression.py \
  --suite psb1 \
  --profile compiled-v2 \
  --grammar-definition configs/grammar/basic/int.json \
  --cases-root data/fixtures/psb1-current \
  --engine gpu --repro-backend gpu --repro-overlap on \
  --blocksize 1024 --population-size 8192 --generations 100 \
  --selection-pressure 2 --mutation-rate 0.5 \
  --mutation-subtree-prob 0.8 --fuel 20000 \
  --seeds 0,1,2,3,4 --eval-test \
  --out-dir logs/psb/compiled-v2
```

The runner requires the definition path and records its file hash. The
definition owns its compiled search and execution limits; a conflicting
explicit fuel value fails at the native CLI boundary.

Use the same cases, resolved grammar content, seeds, population/generation
settings, backend policy, and hardware allocation for comparisons. A
`grammar-population-v2` may be reused for fixed-population timing. A
release-1 `population-seeds` file is not an exact replay source.

## Compare and report

```bash
python3 tools/compare_psb_baseline.py \
  --baseline logs/psb/baseline/summary.json \
  --candidate logs/psb/compiled-v2/summary.json \
  --out logs/psb/compiled-v2/comparison.json
```

When a study has problem-specific tolerances, pass the checked policy under
`configs/psb_tolerances/`. Comparison outputs must record policy, cases, and
grammar identities. Test-set results are reported only when `--eval-test`
was used with matching schemas.

Raw runs and profiler output stay in `logs/`. Commit only compact reviewed
manifests generated by the reporting tools. A release-2 cutover does not itself
establish performance or quality; claims require the completed run matrix and
recorded evidence.
